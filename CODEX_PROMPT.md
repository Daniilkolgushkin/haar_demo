# Промпт для Codex: реализовать Haar Audio Lab

> Этот файл предназначен для передачи Codex в корне нового репозитория вместе с `DESIGN.md`. Если Codex работает непосредственно в репозитории, достаточно вставить текст ниже в первый запрос.

## Задание

Ты — senior C++/WebAssembly + TypeScript frontend engineer. Создай в **текущем репозитории** полностью работающее одностраничное приложение **Haar Audio Lab**, готовое к автоматической сборке и публикации на GitHub Pages. Используй `DESIGN.md` в корне репозитория как **основную обязательную спецификацию**. Если каких-то деталей нет, выбирай простое технически корректное решение и записывай принятые допущения в README; не останавливай работу ради несущественных вопросов.

**Цель пользовательского сценария:** пользователь открывает статическую страницу, загружает локальное аудио, видит **полное** ортонормированное дискретное разложение Хаара, может отключать низкочастотные вклады — целыми масштабами и отдельными коэффициентами — с **оранжевой маской поверх исходной фиолетовой карты**, запускает восстановленный аудиосигнал после истинного обратного DWT, при необходимости сравнивает его с оригиналом.

### Неизменяемые требования

1. Реализуй математику `DWT/IDWT Haar` в **C++**, компилируемом в **WASM**. Используй ортонормированную формулу `(x0±x1)/sqrt(2)`, хранение `[a_J, d_J, ..., d_1]` и полное разложение `J=log2(next_power_of_two(N))`; не ограничивай уровень ради скорости. Выполняй правое symmetric-reflection padding, восстанавливай только исходные `N` отсчётов. Обеспечь моно/стерео без неявного микширования каналов.
2. Используй `Web Worker` для WASM-вычислений, браузерный `decodeAudioData` для входа и `AudioBufferSourceNode` для воспроизведения. Чётко раздели frontend, ядро C++, WASM glue, worker и Web Audio lifecycle.
3. Реализуй кликабельную Canvas time–scale карту: `A_J, D_J … D_1`, горизонтальная ось времени, фиолетовая интенсивность коэффициентов, **чёрные** разметка и подписи. Не называй изображение «точной картой частот». Не создавай DOM-элемент на коэффициент и не пытайся рисовать миллионы маленьких объектов.
4. Оранжевым поверх исходной карты покажи все занулённые элементы: полные выключенные строки и одиночные доступные коэффициенты. Слайдер выключает последовательно `a_J`, `d_J`, `d_(J-1)` …; клики по строкам выключают уровень, по достаточно широким ячейкам — один коэффициент. Добавь zoom, reset, легенду и пояснение об ориентировочных частотах.
5. Две кнопки проигрывания: оригинал и **актуальная** реконструкция (play/stop). Не допусти race conditions между разными файлами и быстрыми изменениями маски. Никаких серверных запросов с аудио.
6. Визуальный стиль минималистичный: фон — **узкий светло-фиолетовый левый край, плавный переход к преобладающему бледно-зелёному**, основная цветовая палитра графика фиолетовая, чёрные оси/подписи, отключенные области оранжевые. Не добавляй дизайнерских блоков, рекламу, тяжёлые UI-фреймворки или декоративные изображения.
7. Обеспечь исправную сборку `npm run build` **с включённым вызовом сборки WASM**. Приложение работает и под `/`, и под `/<repo>/`. Добавь `.github/workflows/pages.yml` для GitHub Pages (C++ + Emscripten + npm ci + tests + build + deploy `dist`). Не добавляй backend и не требуй собственного сервера в production.
8. Добавь проверяемые тесты прямого/обратного преобразования, длины/padding, энергетической нормы, удаления отдельных/всех коэффициентов, стереоканалов, а также smoke tests UI/worker. README должен содержать команды, архитектуру, ограничения памяти/кодеков, инструкции GitHub Pages и честный список выполненных проверок.

### Порядок выполнения

**Шаг A — осмотр и план.** Ознакомься с `DESIGN.md`, осмотри содержимое текущего репозитория, выбери совместимые версии C++, Emscripten, Vite и тестовых зависимостей. Сформируй короткий план внутри своего рабочего вывода, затем переходи к выполнению: не заканчивай на плане.

**Шаг B — математика.** Реализуй C++ библиотеку без зависимости от браузера и тесты на маленькие известные массивы, non-power-of-two длины, случайные сигналы, Parseval. Исправь все тесты до перехода к UI. Затем реализуй C++ session с C ABI с хранением неизменных коэффициентов, эффективным применением маски и реконструкцией.

**Шаг C — приложение.** Реализуй загрузку/проверку аудио, передачу TypedArray в Worker, WASM init, состояния загрузки, Canvas, управление масками, воспроизведение. Следи за тем, чтобы даже при быстрых кликах/новой загрузке не использовались устаревшие результаты. Для больших данных передавай `ArrayBuffer` как transferable, где возможно.

**Шаг D — публикация.** Добавь CI workflow, правильный Vite base-path, скрипты `wasm:build`, `build`, `test`, `.gitignore` для генерируемого WASM, корректное копирование WASM в `dist` через Vite asset pipeline. Проверь production build и при доступности браузера — `npm run preview` в Chromium/Firefox, включая subpath или эквивалентный smoke check.

**Шаг E — контроль.** Прогони `npm run test:core`, JS tests, TypeScript typecheck, `npm run build` и, если среда позволяет, браузерный end-to-end сценарий «upload → DWT → выключить несколько нижних полос → увидеть orange overlay → реконструкция → playback → reset». Если что-то не проверено, не заявляй, что проверено.

### Что считать ошибками реализации

- Демо с заранее встроенной синусоидой **вместо** реальной загрузки файла.
- FFT/CWT, оформленные под Хаара; Haar, реализованный исключительно на JS без реального WASM.
- Декомпозиция на фиксированные 8 уровней для длинного аудио.
- Фильтрация звука EQ вместо `IDWT(mask(DWT(x)))`.
- Выключение «полос» лишь на экране, но не в коэффициентах восстановления.
- Невозможность прослушать результат, многократный `start()` одного `AudioBufferSourceNode`, неотменяемые устаревшие worker results.
- Ручные абсолютные пути `/assets` или `/pkg` приводят к 404 на GitHub Pages `/<repo>/`.
- Молчаливое удаление одного стереоканала, сброс sample rate или усечение аудио.
- Проект, работающий только при `npm run dev`, но не через `npm run build`/Pages.
