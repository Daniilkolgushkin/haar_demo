# Haar Audio Lab — техническое задание и заметки для Codex

**Статус:** спецификация MVP, готовая к реализации.  
**Цель:** статическое одностраничное веб-приложение для исследования полного дискретного разложения аудиосигнала по ортонормированному базису Хаара, подавления отдельных коэффициентов и/или целых масштабов и прослушивания обратного преобразования.  
**Размещение:** GitHub Pages (включая проектный URL `https://<owner>.github.io/<repo>/`).  
**Основной стек:** C++20 + WebAssembly (Emscripten), TypeScript, Vite, Canvas 2D, Web Audio API. Без backend, серверного хранения аудио и внешних API.

---

## 1. Ключевые решения и интерпретация требования

Это не FFT-спектрограмма, не CWT и не свёрточный фильтр. Используется **ортонормированное, децимированное многомасштабное DWT Хаара** (Haar = Daubechies-1 / `db1`) и точное обратное IDWT из модифицированного набора коэффициентов.

1. **«Максимально возможный порядок».** Для исходных `N` отсчётов на канал берём `M = next_power_of_two(N)`, `J = log2(M)`. Декомпозируем до единственного аппроксимирующего коэффициента `a_J[0]`, т. е. выполняем **все `J` уровней**, а не `J = 5..8` или произвольную «полосу частот». Единственный предел — явно объявленный ресурсный лимит на размер массива, а не уменьшение порядка.
2. **Дополнение справа.** По умолчанию *symmetric reflection*: продолжаем сигнал отражением относительно его правого граничного отсчёта, повторяя отражения при необходимости, до `M`. Для `N=1` — повторение единственного отсчёта. Различать это **явное предварительное дополнение до степени двойки** и встроенные boundary modes PyWavelets; это не обязательно побитно совпадающие операции на произвольной длине. После IDWT оставляем первые `N` отсчётов. Режим должен быть задокументирован и протестирован; при переключении на zero padding потребуется согласованно изменить тесты и описание.
3. **Каналы.** Поддерживаются моно и стерео. Левый и правый каналы преобразуются независимо; **одна и та же маска коэффициентов** применяется к обоим каналам, чтобы сохранить стереопанораму. Многоканальные файлы (>2 каналов) в MVP отклоняем с понятным сообщением, не скрываем автоматический downmix.
4. **«Низкие частоты».** Самый крупномасштабный вклад — `a_J` (для полностью двоичной длины — DC), далее `d_J`, `d_{J-1}`, …, `d_1`. Чем выше `j`, тем крупнее масштаб и ниже *характерная* частота. **Это НЕ непересекающиеся идеальные полосы Гц**: фильтры Хаара имеют широкие, перекрывающиеся частотные отклики. Значение на слайдере «≈ Гц» — только ориентир.
5. **Что значит «выключить».** Значение соответствующего коэффициента Хаара заменяется на `0` *только перед обратным преобразованием*; исходные коэффициенты остаются неизменными. Выключить можно целый уровень `d_j`, один коэффициент `d_j[k]` (при достаточном зуме), а также `a_J[0]`. Общий элемент управления отключает подряд самые низкочастотные уровни.
6. **Исходная визуализация остаётся исходной.** Сиренево-фиолетовая карта рассчитана по исходным коэффициентам; отключения показываются оранжевой **маской поверх карты**, а не перерисовывают исходную энергию как нулевую. Отдельно допускается компактная осциллограмма результата.
7. **Файлы остаются локально.** Чтение `File` и декодирование, вычисления и проигрывание выполняются в браузере. Ни аудио, ни его производные не отправляются на сервер. Это не утверждение об отсутствии обычных сетевых запросов к GitHub Pages за ресурсами приложения.

### Необязательные, но явно разрешённые расширения ПОСЛЕ MVP

Экспорт обработанного WAV (16/24-bit PCM с dither по необходимости либо 32-bit float), увеличение/настройка лимита, выбор канала для визуализации, спектрограмма FFT для сравнения, переключение граничного продолжения, отдельный тренажёр по коэффициентам. **Не делать их вместо основного функционала**.

## 2. Функциональный сценарий

1. Пользователь открывает страницу и видит заголовок **Haar Audio Lab**, короткий текст о DWT, область загрузки файла (`input[type=file]`, drag-and-drop как enhancement), пустое поле будущей визуализации.
2. Загружает поддерживаемый браузером локальный аудиофайл (WAV, MP3, Ogg, FLAC и др. — **доступность конкретного кодека зависит от браузера**; не обещать универсальную поддержку). Сначала проверить размер файла, корректность декодирования, число каналов и размер декодированного сигнала.
3. Декодировать через Web Audio API. Помнить, что `decodeAudioData()` возвращает `AudioBuffer` **в sample rate используемого AudioContext**, то есть возможен ресемплинг; показывать фактический `sampleRate` анализируемого буфера, не объявлять его исходным sample rate файла.
4. Отправить копии PCM-каналов в выделенный Web Worker с помощью transferable `ArrayBuffer`; выполнить в WASM полное DWT. В UI вывести метаданные: имя, длительность, число каналов, фактическая частота дискретизации, `N`, `M`, `J`, тип padding.
5. Нарисовать карту коэффициентов: строки сверху вниз — `a_J`, `d_J`, `d_{J-1}`, …, `d_1`, горизонтальная ось — время. Сверху/снизу добавить компактную осциллограмму исходного аудио (желательно) и черную разметку.
6. Пользователь может:
   - ползунком выключить **префикс** от самых низких масштабов (`a_J`, затем `d_J`, `d_{J-1}`, …);
   - нажатием на метку строки выключить/включить **весь уровень**;
   - щелчком по отчётливо видимому прямоугольнику коэффициента выключить/включить **конкретный коэффициент**; недоступные мелкие ячейки требуют горизонтального увеличения;
   - выполнить «Сбросить изменения».
7. Выключенные области отмечаются полупрозрачным оранжевым с сохранением видимого фиолетового фона; полностью выключенная полоса закрашивается оранжевым по всей ширине. Черная разметка сохраняется поверх маски. Отображается число выключенных коэффициентов и уровней.
8. После изменения маски выполняется обратное IDWT в Worker; обработанный буфер передаётся в основной поток; пользователь может запустить/остановить **исходный** и **восстановленный** звук. Вторая кнопка всегда воспроизводит *последнюю актуальную* реконструкцию, а не предыдущий результат. Одновременное проигрывание двух источников запрещено; возможна остановка текущего и запуск другого.
9. Загрузка следующего файла отменяет/игнорирует результаты предыдущих асинхронных задач (session ID / generation token), останавливает звук и освобождает устаревшие буферы.

### Управление низкочастотным порогом

Слайдер — целое `q ∈ [0, J+1]`: `q=0` — ничего не выключено; `q=1` — только `a_J`; `q=2` — `a_J + d_J`; ...; `q=J+1` — выключено всё, выходная тишина. Для `q≥2` грубый верхний ориентир подавляемого диапазона: `f ≈ sampleRate / 2^(J+2-q)` Гц. Для `q=1` подписать **«только DC»**, для `q=0` **«без изменений»**. Все подписи должны включать `≈`, а подсказка — предупреждение об отсутствии резкой границы частот.

Слайдер при изменении **сбрасывает индивидуальные исключения** и задаёт последовательную маску. При ручном изменении строки/ячейки UI переключается в состояние **«Выборочно»**, не показывает ложное значение общего порога. Нажатие «Сбросить» возвращает `q=0`, без выключений. **UX-важно:** для типичного длинного аудио первые несколько крупных масштабов могут лежать значительно ниже слышимого диапазона; добавь метки на слайдере и один-два быстрых ориентира **«≈ 80 Гц»** / **«≈ 200 Гц»**, выбирающие ближайшее существующее значение `q` (без обещания резкой частотной границы). По умолчанию `q=0`.

### Интерфейс выбора отдельного коэффициента

Для `d_j[k]` его область поддержки в исходной шкале времени — `[k·2^j, (k+1)·2^j)` отсчётов padded-сигнала, обрезанная по `N`. Аппроксимация `a_J` занимает всю длительность. Click по ячейке переводится в индекс по `j` и координате `x`; действие над **одним** коэффициентом допускается, если его видимая ширина ≥ **8 CSS px**. Если меньше, показать подсказку «Увеличьте масштаб или отключите уровень целиком»; нельзя молча отключать тысячи коэффициентов одной ячейкой.

Сделать горизонтальное масштабирование (например, колесо с Ctrl/кнопки `+`/`−`) и панорамирование / нижнюю полосу прокрутки; сохранять ось времени, отметки и оранжевую маску согласованными. Для MVP достаточно простого zoom от 1 до 32 с клавишами `+`, `−` и скроллом; адаптивно поддерживать ширину графика.

## 3. Математическая спецификация (строго обязательно)

Пусть padded-сигнал `x` имеет `M=2^J` вещественных отсчётов. На каждом уровне соседние пары преобразуются ортонормированно:

```text
a[k] = (x[2k] + x[2k+1]) / sqrt(2)
d[k] = (x[2k] - x[2k+1]) / sqrt(2)
```

После первого шага рекурсивно преобразовывается **только массив `a`**. Полный результат хранить в едином packed-массиве длины `M`:

```text
[a_J[0] | d_J[0] | d_(J-1)[0..1] | ... | d_2[...] | d_1[...]]
```

Это стандартный порядок `[cA_J, cD_J, ..., cD_1]`. При нулевой индексации:

- `a_J` лежит в `[0,1)`;
- `d_j` лежит в `[M/2^j, M/2^(j-1))`, число коэффициентов равно `M/2^j`;
- позиция отдельного коэффициента `d_j[k]` = `M/2^j + k`, `0 ≤ k < M/2^j`.

Для обратного преобразования последовательно восстанавливать `a_(j-1)` из `a_j` и `d_j`, начиная с `j=J`:

```text
x[2k]   = (a[k] + d[k]) / sqrt(2)
x[2k+1] = (a[k] - d[k]) / sqrt(2)
```

**Ни в одной процедуре нельзя ошибочно применять повторный DWT к detail-ветви.** Не путать `J` (число уровней) с частотой или размером окна. В DWT есть и очень крупные, практически инфразвуковые масштабы — это ожидаемо при полном разложении длинной записи.

При нулевой маске `IDWT(DWT(padded(x)))` должен восстановить весь padded-сигнал с ошибкой численного округления; первые `N` отсчётов — исходное аудио. Для всех отключённых коэффициентов получаются нули. Поскольку базис ортонормирован, справедлива проверка энергии `sum(x_i²) ≈ sum(c_i²)` **на padded-сигнале** (Parseval).

**Изменение маски**: исходный packed-массив никогда не изменять. Для реконструкции создать рабочую копию, занулить выбранные блоки и отдельные коэффициенты, выполнить IDWT. Один набор коэффициентов на канал, одинаковая маска индексов для обоих.

### Маска без миллионов UI-элементов

В памяти UI хранить:

```text
baseOff[0..J]          // строки: a_J, d_J, ..., d_1; true => вся строка выключена
exceptions: Set<u32>   // абсолютные индексы packed-коэффициентов,
                       // у которых состояние противоположно baseOff для своей строки
```

Эффективный статус ячейки: `baseOff[row] XOR exceptions.has(packedIndex)`. Полное отключение строки — изменение одного флага и очистка исключений в этой строке. В worker/WASM можно сформировать рабочие коэффициенты, занулить блоки, затем восстановить значения исключений, где `baseOff=true`, либо занулить исключения, где `baseOff=false`. Это предотвращает пересылку маски размера `M` при каждом клике. Маска в обоих каналах применяется синхронно.

**Защита от переполнения**: после обратного преобразования вычислить peak абсолютной величины по всем каналам. При `peak > 1` применить **единый** линейный коэффициент `gain = 0.999 / peak` ко всем каналам, показать надпись «Снижен уровень на X dB для предотвращения clipping». Не применять лимитер, обрезание или нормализацию в остальных случаях. Отсутствие маски должно восстанавливать тот же PCM в пределах численной погрешности.

## 4. Визуализация

**Тип:** интерактивная time–scale coefficient map (scalogram-like view of decimated Haar DWT), а не STFT-спектрограмма.

- **Горизонталь:** время от `0` до `N/sampleRate` секунд; отметки времени черные, при zoom — динамические.
- **Вертикаль:** `A_J`, `D_J`, ..., `D_1`, сверху низкие характерные частоты, снизу высокие. Подписи `j`, размер поддержки `2^j` отсчётов и при достаточном месте **примерный** частотный диапазон / верхний ориентир в Гц (`sampleRate/2^j`); подписи `DC` и `≈ Hz` — явно.
- **Ячейка:** один коэффициент задаёт свой временной прямоугольник, шириной `2^j` в отсчётах. В полной ширине графика на мелком уровне их может быть миллионы — **запрещается создавать DOM-элемент на коэффициент**.
- **Рендер:** `CanvasRenderingContext2D`, `devicePixelRatio` с верхним пределом (например 2); геометрия/подписи поверх графика Canvas или отдельный компактный слой. Целевая ширина rasterization — не более числа экранных пикселей. При zoom и resize пересчитать агрегаты; при изменении маски пересчитать только оранжевый overlay, а не DWT.
- **Яркость:** magnitude/energy, не ошибочно названная «амплитуда частоты». Для сопоставимости масштабов учесть нормировку `|c_j[k]| / sqrt(2^j)`; стерео агрегировать через RMS каналов. Для каждого горизонтального пикселя внутри строки агрегировать коэффициенты, пересекающие временной bin, через RMS; использовать мягкое логарифмическое отображение яркости и устойчивый reference scale (например 98–99-й перцентиль значений detail-строк); DC не должен «забивать» шкалу цвета. Подписать, что это **величина коэффициентов/вкладов**, не спектральная плотность и не PSD. Величины отображать в фиолетовой гамме, без rainbow colormap.
- **Оранжевая маска:** каждый отключённый коэффициент закрашивает свою область поддержки в своей строке; полная строка — вся полоса. Для слишком мелких коэффициентов в одном отображаемом пикселе можно агрегировать долю выключенных и показывать степень оранжевого заполнения/полосовую штриховку. Полностью выключенные части должны быть ясно различимы, черная сетка — поверх.
- **Осциллограмма:** тонкий, необязательный, но желательный график огибающей оригинала и/или восстановленного сигнала, без отрисовки каждого семпла отдельным draw-call (min/max per pixel).
- **Легенда:** «Фиолетовый — исходные коэффициенты», «Оранжевый — занулены при восстановлении».

Можно немного изменить структуру, но **разделение C++-ядра, WASM-обёртки, Worker, аудио и Canvas** обязательно.

**Main thread:** `File` -> `ArrayBuffer` -> `decodeAudioData()` -> `AudioBuffer` (исходный, для A/B прослушивания) -> копии Float32Array PCM для передачи в Worker. На каждый upload/изменение маски — monotonically increasing `sessionId` и `requestId`.

**Worker:** `init(wasmUrl)` один раз; `newSession(pcm, sampleRate, channelCount, N)` -> padding, DWT, метаданные -> компактные данные для Canvas при запрошенном разрешении/zoom; при updateMask — IDWT из исходных коэффициентов -> transfer восстановленного `ArrayBuffer`/каналов -> main. Нет постоянных копий всех версий реконструкции. При замене файла уничтожить прежнюю WASM-сессию. Показывать состояние `loading / decoding / transforming / ready / reconstructing / error`.

**UI:** хранит контролируемую маску, начальные metadata, параметры viewport; никогда не интерпретирует пиксели как «точные интервалы частоты».

**WASM API:** формат ABI Codex может выбрать сам, но JS <-> C++ обменивать typed arrays, а не миллионы объектов. Session хранит packed-коэффициенты для каждого канала; функции `transform`, `renderBins`, `reconstruct`. Трансформация и реконструкция — **в WASM**, нельзя подменить вычисления JS-реализацией и назвать проект WASM.

**Передача буферов:** большие TypedArray передавать как transferable `ArrayBuffer` без неявного structured-clone копирования, где это применимо. Отправляемую ArrayBuffer после transfer нельзя использовать в отправившем контексте — использовать заранее созданные копии PCM, исходный `AudioBuffer` сохранить для прослушивания.

### Ограничение ресурсов

Начальная политика MVP: допускается `M ≤ 2^23` padded-отсчётов **на канал** (до ~190 с при 44.1 kHz, чуть меньше ~175 с при 48 kHz); для 2 каналов это серьёзный расход памяти, поэтому предусмотреть более раннее предупреждение при `M > 2^22`, отлов allocation errors и понятное сообщение при превышении лимита. Это сознательное **ограничение размера входа**, а не глубины разложения: для каждого принятого файла `J=log2 M` без исключений.

Лимит хранить в `config.json` (`maxPaddedSamples`), передавать в C++ через compile definition и импортировать в TypeScript;, документировать в UI/README; не создавать неверный `AudioBuffer` и не обрезать аудио молча. **Объём файла в байтах не равен объёму декодированного PCM**; проверить byte size до декодирования (например, мягкий предупреждающий порог 100 MiB) и `M` после декодирования. Реализовать graceful error с предложением выбрать короткий файл. Более поздняя версия может поддержать выбор участка записи, но MVP не обязан скрыто сэмплировать/downmix/уменьшать sample rate.

- `npm run dev` работает локально; `npm run build` гарантированно **сначала собирает WASM**, затем Vite (посредством `prebuild` или явного script); `npm run preview` работает после сборки.

Скрипт `scripts/build-wasm.mjs` задаёт экспорт C ABI и пишет `src/generated/haar/haar.js` + `haar.wasm`. TypeScript glue управляет выделением/освобождением памяти и копиями typed arrays. Worker импортирует `.wasm?url`, передаёт URL через `locateFile`; Vite публикует оба ресурса с учётом base path. Никаких Emscripten threads/SharedArrayBuffer.

## 6. Тесты и критерии приёмки

### Математика (обязательные C++ unit tests (native))

1. **Известный вектор:** `[1,2,3,4]` -> `[5, -2, -1/√2, -1/√2]` в порядке `[a_2, d_2, d_1[0], d_1[1]]` (проверить! `a2=(1+2+3+4)/2=5`, `d2=(1+2-3-4)/2=-2`).
2. **Константа:** для `x=[c;M]` все detail-коэффициенты ≈ 0, `a_J=c√M`; выключение только `a_J` -> нулевой звук.
3. **Impulse и step:** проверить знак/порядок коэффициентов и корректность реконструкции.
4. **Round-trip:** длины `1`, `2`, `3`, `7`, `8`, `1000`, `65537` и случайный вектор; `max |x - IDWT(DWT(x))|` на первых `N` отсчётах не более обоснованного `float32` допуска (`~1e-4` для типовых тестов); отдельно сравнить padded-вектор. При отсутствии маски **нет сдвига и изменения длительности**.
5. **Parseval:** для padded-вектора энергия до/после DWT совпадает в пределах погрешности.
6. **Полная маска:** выход — нули; **пустая маска:** исходные PCM; **строка off + исключение on** восстанавливает ровно один коэффициент без разрушения остальных.
7. **Stereo:** одинаковые маски в обоих каналах, без cross-talk; число выходных отсчётов равно `N` у обоих.
8. **Один коэффициент:** выключенный `d_j[k]` влияет на соответствующий временной интервал поддержки (за исключением тонкостей граничного продолжения).
9. **Сравнение с независимым эталоном:** для dyadic-вектора проверить `[cA_J,cD_J,…,cD_1]` с PyWavelets `wavedec(x, 'haar', level=J)` (или с небольшим отдельно написанным Python-эталоном), не включая в production Python.
10. **Корректность отражения:** для непрерывного константного сигнала длины `N`, не равной степени двойки, явное padding должно оставить все detail≈0.

*Важно:* вектор `[1,2,3,4]` при принятой нормировке действительно имеет `d2=-2`, но `d1=[-1/√2,-1/√2]`; не использовать альтернативную нормировку без изменения всех тестов.

### Браузер, интерактивность и воспроизведение

- WAV mono/stereo загружается, декодируется и действительно проходит через WASM. Приложение не зависает при трансформации 30–120 сек аудио: тяжёлые вычисления выполняются в Worker, есть индикатор и корректные состояния кнопок.
- Осмысленные примеры: чистый DC, синус 40 Hz, синус 1 kHz, импульс, короткий stereo tone; тестировать как селекцию коэффициентов, так и слышимую реконструкцию. Не утверждать резкого подавления синуса при «cutoff ≈ 50 Hz».
- `q=0`: обработанный сигнал совпадает с исходным с допуском F32; `q=J+1`: тишина; `q=1`: DC убран (относительно padded-сигнала).
- Отключение строки делает всю строку оранжевой; индивидуальный toggle — только соответствующую ячейку; back toggle восстанавливает оригинальное состояние; zoom корректно меняет hit testing.
- Playback: новый `AudioBufferSourceNode` **при каждом запуске**; `AudioContext.resume()` из пользовательского жеста, stop/ended, загрузка нового файла, A/B без наложения источников.
- После быстрого изменения маски UI не запускает устаревший вариант реконструкции (generation token/request ID). Результаты от предыдущего файла игнорируются.
- Ошибки: пустой файл, повреждённый файл, codec not supported, >2 каналов, слишком долгий/большой файл, невозможность init WASM, невозможность декодирования, ограничения памяти.
- Test production build: проверить загрузку `.wasm`, отсутствие 404 на статические assets под **`/repo/`**, отсутствие абсолютных ссылок на `/assets/`, отсутствие CORS/server calls за аудио.
- Функциональные проверки Firefox + Chromium desktop; мобильная ширина/сенсорный ввод — best effort, без обещаний поддерживать произвольно большие аудиофайлы на малой памяти.

### Определение готовности (Definition of Done)

Работа завершена только когда есть **реально запускаемый** репозиторий, а не красивые макеты или отдельные формулы; `npm run test:core` проходит, `npm ci && npm run build` проходит, в `dist` есть WASM и связанные assets, основная последовательность «загрузить → увидеть DWT → выключить → увидеть оранжевую маску → услышать IDWT → восстановить исходное состояние» проверена в браузере, и GitHub Pages workflow присутствует. В README есть локальный запуск, архитектура, предупреждение о приближённых частотах и инструкции деплоя. Если Codex не может открыть браузер или проверить deploy, он обязан явно перечислить непроверенное и не заявлять об успешной публикации.

## 7. Предупреждения для реализации

- Порядок `d_J … d_1` не путать с «низкие частоты = маленький номер уровня». Здесь **большие `j` → грубые, низкочастотные вклады**.
- У DWT Хаара нет независимых «частот» в каждом столбце. Нельзя выдать высоту строки за точный тон в Гц или выполнить FFT и назвать это DWT.
- Не пытаться рисовать миллионы `rect` в SVG/DOM: Canvas, экранное агрегирование.
- Не подменять восстановление приблизительной фильтрацией: всегда `IDWT(mask(DWT(x)))`.
- Не терять sample rate, каналы и длину. Не принудительно сводить стерео в моно.
- В исходном decoded AudioBuffer sampleRate может быть изменён Web Audio API. Сообщать **фактически обработанный** rate.
- `AudioBufferSourceNode` одноразовый. Не использовать `start()` повторно у одного экземпляра.
- Простая модуляция яркости и цветовые маски не должны менять сами коэффициенты.
- Шум и цифровой clipping после зануления ортогональных компонент возможны из-за изменения peak waveform: выполнять только прозрачный peak-guard, показывать его действие.
- Побочный эффект padding на правой границе не выдавать за «свойство Хаара»; отдельный тест на неравную степень двойки.
- Обновление данных после `postMessage` безопасно только с учётом transfer и отмены старых сессий.
- `npm run build` должен воспроизводиться на чистой машине. Нельзя проверять только `npm run dev`, забыв публикацию под subpath.
